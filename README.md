# RSOCKET

Инструмент, который читает описание API платёжного провайдера в формате OpenAPI и
собирает по нему заготовку интеграции. На выходе — сервис на Ruby по контракту
заказчика, инструкция по подключению, примеры запросов и ответов, тесты.

Смысл в том, чтобы не писать руками одно и то же для каждого нового провайдера.
Инструмент сам разбирается, какой метод создаёт платёж, какие статусы означают успех,
какие ошибки можно повторять, — и честно говорит, в чём он не уверен.

## Как поднять у себя (macOS, с нуля)

Ruby ставим через rbenv, чтобы у всех была одна и та же версия.

1. Поставьте rbenv:

   ```
   brew install rbenv ruby-build
   ```

2. Допишите в конец файла `~/.zshrc` две строки:

   ```
   export PATH="$HOME/.rbenv/bin:$PATH"
   eval "$(rbenv init - zsh)"
   ```

3. Перезапустите терминал — иначе новые строки не подхватятся.

4. Поставьте нужную версию Ruby:

   ```
   rbenv install 3.3.12
   ```

5. Перейдите в каталог проекта и поставьте гемы:

   ```
   gem install bundler
   bundle install
   ```

Версию Ruby отдельно переключать не нужно: она записана в файле `.ruby-version`,
rbenv берёт её оттуда сам, как только вы заходите в каталог проекта.

## Как проверить, что всё поднялось

Две команды. Первая гоняет тесты и линтер:

```
bundle exec rake
```

Вторая проверяет само окружение — версию Ruby, гемы, наличие каталогов:

```
bundle exec bin/rsocket doctor
```

Если обе прошли без ошибок, можно работать.

## Что где лежит

| Каталог | Что там | Кто отвечает |
|---|---|---|
| `lib/rsocket/spec/` | чтение файла с описанием API и раскладка в общий вид | Амир |
| `lib/rsocket/ir/` | классы разобранного описания | Амир |
| `lib/rsocket/mock/` | поддельный сервер провайдера для проверок | Амир |
| `examples/` | примеры описаний API | Амир |
| `lib/rsocket/classify/` | распознавание: что за что отвечает в описании | Савелий |
| `lib/rsocket/dictionaries/` | словари: синонимы, статусы, ошибки, веса | Савелий |
| `lib/rsocket/manifest/` | файл с догадками инструмента, который можно править руками | Савелий |
| `lib/rsocket/report/` | отчёт: что распознано уверенно, а что требует проверки | Савелий |
| `reference/` | образцовый сервис, написанный руками | Иван |
| `lib/rsocket/templates/` | шаблоны выходных файлов | Иван |
| `lib/rsocket/generate/` | сборка выходных файлов по шаблонам | Иван |
| `lib/rsocket/runtime/` | заглушки контракта заказчика | Иван |
| `bin/` | команды: `integrate` и `rsocket` | Капитан |
| `output/` | сюда складывается результат работы инструмента | — |
| `spec/` | тесты на сам инструмент | каждый на свою часть |

## Правила

Ограничения хакатона, нарушать нельзя:

- Весь код только на Ruby.
- Нейросети внутри решения запрещены. Инструмент должен работать сам, без обращений к
  моделям во время прогона.
- Сторонние библиотеки — только опенсорсные гемы.
- Никаких названий конкретных провайдеров в `lib/`. Всё, что зависит от провайдера,
  живёт в `lib/rsocket/dictionaries/` и `lib/rsocket/templates/`.
